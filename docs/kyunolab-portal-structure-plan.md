# Kyunolab Portal Structure Plan

This is an internal working plan for the Kyunolab redesign. It is not a public
visitor page. Use it as the shared standard for future work so the site can be
expanded without replacing the agreed structure each time.

## Core Principle

Kyunolab should feel like a large text-first city, not a menu list.

- Buildings are the value: Archive articles, Creator Library pages, and Tools.
- Roads are the internal links between those buildings.
- Signs are the top navigation, sidebars, breadcrumbs, section labels, and hub links.
- Roads and signs matter, but they must not become the main attraction.

The site should show that there are many valuable places to read, use, and
return to. Menus and internal links should help visitors move quickly without
getting lost.

## Main Site Axes

### Archive

Archive is the central content hub.

- Main value: story articles.
- Structure: articles, categories, tags, motifs, related articles, reading paths.
- Role: the largest body of content and the main entry point for search traffic.
- Internal roads:
  - Archive to Archive through related stories, categories, tags, motifs.
  - Archive to Mystery Board through source and reading guides.
  - Archive to Creator Library through related scripts/resources.
  - Archive to Tools through relevant utilities and examples.

### Creator Library

Creator Library is a second content axis, not only a footer link.

- Main value: scripts, creator resources, production material, and story-to-script bridges.
- Structure: library home, script categories, board/resources, related archive source.
- Internal roads:
  - Library to Archive through original story/source links.
  - Library to Tools through production helpers, motif finders, and path builders.
  - Library to Mystery Board through writing/source/structure guides.

### Tools

Tools are not archive-style pages. Each tool page should feel like a stadium:
the tool field is the main event.

- Main value: usable tools.
- Structure: tool input/result first, short explanation second, related content after.
- Do not overload tool pages with roads and signs.
- Internal roads:
  - Tool to Archive through examples and results.
  - Tool to Library through related creator resources.
  - Tool to Mystery Board through explanation guides.

Recommended tool page ratio:

- Tool field/result: about 75%.
- Explanation: about 10%.
- Related links: about 10%.
- Ads/support: about 5%, placed away from the active tool field.

### Mystery Board

Mystery Board is an information center and guide layer.

- Main value: public guidance, source status, reading paths, SEO-friendly explainers.
- Role: helps visitors understand how to read and classify strange stories.
- It supports Archive, Library, and Tools.
- It should connect outward to all three axes.

### Hub

Hub is a small public activity building, not a main content axis.

- Possible content:
  - Bookmark Kyunolab instructions.
  - Support/donation information.
  - Events.
  - Mini-book campaigns.
  - Share/SNS activity.
  - Topic suggestions.
  - Future community or partnership activity.
- Hub should be visible but not louder than Archive, Library, or Tools.

## Top Navigation

Top navigation should be grouped, not a long category list.

Recommended top-level labels:

- Archive
- Mystery Board
- Creator Library
- Tools
- About
- Hub

Archive, Board, Library, and Tools can have expandable menu panels. The menu
itself should remain a sign system, not the main visible content.

The search box should exist but should not dominate the page. Kyunolab is not a
search engine home page. It should be easy to search, but the visible value
should be articles, guides, scripts, and tools.

## Homepage Structure

The homepage should be additive. Do not replace the agreed structure whenever a
new need appears. Add new blocks in the right place.

Recommended order:

1. Compact header with grouped navigation and modest search.
2. Top ad slot, if ads are used.
3. Featured/known story area using real archive articles.
4. Headline Desk: mixed individual links, not just categories.
5. Reader Paths: curated blocks such as road legends, internet folklore, older folklore, source-aware reading.
6. Motif Lanes: subject/motif groupings such as mirrors, roads, water, creatures, warnings.
7. Archive Shelves: category-based article groups.
8. Board, Library, Tools, and Hub blocks.
9. Footer and sitemap-style discovery.

Use real existing articles wherever possible. If collection pages do not exist
yet, use curated homepage blocks instead of pretending collection articles exist.

Avoid using "Popular" as a traffic claim until there is real traffic data.
Prefer labels such as:

- Start Here
- Featured
- Known Stories
- Recommended
- Essential Reads

## Sidebar Roles

Sidebars should vary by page type. Do not use one sidebar everywhere.

### Homepage

- Usually no left sidebar.
- Right sidebar can show:
  - Ad slot.
  - Known/featured stories.
  - Start Here guides.
  - Tools preview.
  - Hub/support/events.

### Archive Article

Left sidebar:

- Table of contents.
- Current article guide.
- Category/source path.

Right sidebar:

- Ad slot.
- Related Archive articles.
- Related Mystery Board guides.
- Related Creator Library material.
- Related Tools.

Existing article structures such as reading bridge, related articles, tags,
source notes, and previous/next links should be preserved and strengthened, not
removed.

### Category Page

Left sidebar:

- Category navigation.
- Category subtopics or page navigation.

Right sidebar:

- Category highlights.
- Related categories.
- Related motifs/tags.
- Board guide.
- Ad slot.

### Mystery Board

Left sidebar:

- Board guide navigation.
- Current guide sections.

Right sidebar:

- Related Archive articles.
- Related Library resources.
- Related Tools.
- Ad slot.

### Creator Library

Left sidebar:

- Resource/format navigation.
- Script section navigation where useful.

Right sidebar:

- Original Archive source.
- Related Library pages.
- Related Tools.
- Board guide.
- Ad slot.

### Tools

Sidebars should be minimal.

- Do not place a heavy link maze beside the tool input field.
- Use a short right sidebar or below-tool area for:
  - Archive examples.
  - Related Board guide.
  - Related Library resource.
  - Ad slot below or after the main tool area.

### Hub

Sidebar can show:

- Bookmark instructions.
- Support/share actions.
- Events.
- Return roads to Archive, Library, and Tools.

## Internal Linking Principles

The network should be bidirectional.

- Archive <-> Library
- Archive <-> Tools
- Library <-> Tools
- Mystery Board <-> Archive
- Mystery Board <-> Library
- Mystery Board <-> Tools
- Hub -> all major axes, but quietly

Archive can remain the central hub, but the whole site should not become
Archive-only. Library and Tools need direct roads to each other and back to
Archive.

## Ads

Advertising should be planned as reserved land, not inserted later as clutter.

Possible ad locations:

- Header/top banner.
- Right rail.
- In-feed between homepage sections.
- Article middle slot.
- Article bottom slot.
- Mobile inline slots.
- Tool pages only away from the active tool field.

Ads should not break reading flow, tool use, or the site's calm text-first
identity.

## Color and Branding

Keep the existing icon and brand assets. The logo's orange-and-black crow mark
is the strongest brand cue, so the portal direction should feel like a bright
paper archive with ink-black structure and warm orange accents.

Do not replace:

- favicon files.
- icon-192.png.
- icon-512.png.
- apple touch icon.
- manifest icon references.
- existing brand mark identity.

Recommended color usage:

- Off-white/warm paper: main background and reading areas.
- Ink black/charcoal: structural lines, featured panels, headings, and strong contrast.
- Logo orange: active navigation, buttons, section labels, and small friendly brand cues.
- Soft orange/cream: ad placeholders, hub/support areas, and secondary panels.
- Existing navy can remain as a minor support color where it already appears, but it should not overpower the logo-based direction.

The crow/skull idea should stay mascot-like and friendly, not horror-heavy. The
redesign should preserve readability while making the information architecture
feel larger, warmer, and more Kyunolab-specific.

## Implementation Order

Do not apply every change at once.

Recommended sequence:

1. Confirm this structure plan.
2. Home redesign first.
3. Article sidebar refinement.
4. Category page refinement.
5. Mystery Board cross-link refinement.
6. Creator Library visibility and cross-link refinement.
7. Tools placeholders and later real tool pages.
8. Hub page.
9. Ad slot refinement.
10. Full build, validation, visual check, then deployment only when explicitly requested.
